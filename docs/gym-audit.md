# Gym exercise visual audit

Audit only — nothing in the app was changed. Generated by `scripts/vision-audit/build_gym_report.py` from the real resolver (`resolveExercise` + style-variant chips) on `origin/main` @ the commit this file lands on.

**How each row was checked:** the animated webp was viewed at 4 frames (start, ¼, ½, ¾) and compared against (1) the exercise named on the card/sheet, (2) the highlighted muscle vs. the declared target/secondary, (3) the exercise's equipment vs. the tab it sits under, (4) the steps + card cue text. Every suggested replacement id was viewed the same way. Vision was done in-session (no paid API).

A *row* is one (slot, tab, exercise): the tab's default plus every style-variant chip, plus any id filed under the tab that the UI can't reach. Slots are shared across plans, so a fix to a gym slot also changes the calisthenics/travel tabs listed in the second row — they're audited here too.

Candidate rules applied: EDB 3D animation first; free-exercise-db photo only as a flagged last resort (⚠); no bars/benches/bands on travel or floor slots; no exercise reused by another slot; where EDB has nothing right for a tab, **REMOVE the tab** rather than keep a wrong one.

## Method notes

- EDB highlights quads on squats/lunges even when the declared target is glutes; that alone was not marked a mismatch.
- The card title is the catalog variation name (or the chip name), the cue comes from `catalog.plans.<plan>.cues`, the muscle tags + steps come from the exercise; all were compared to the animation.
- Slot names that hide a reused id (e.g. Leg Press under both Squat and Lunge) are flagged as duplicates.
- Re-run: `scripts/vision-audit/dump_gym_matrix.ts` → `gym_frame_strips.py` (view the strips) → edit `gym_verdicts.py` → `build_gym_report.py`.
