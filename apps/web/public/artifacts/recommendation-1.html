★ Recommendation #1 — explained

Hevy's exercise atom + your Movement slot

Keep the battle-tested exercise entity the whole industry uses, and add the one layer they all skip: a real, swappable movement slot. You get proven foundations and your differentiator.
Gym Tracker · the recommended architecture
In one sentence: A Program (Pull) is a list of Movement slots (Vertical pull, Horizontal row…). Each slot holds one chosen exercise (Cable Lat Pulldown, by stable ID) plus a list of alternatives you can swap to — and every exercise carries its own gif, muscle tag, equipment and steps.

The two building blocks

Block 1 · borrowed from Hevy (proven)
ExerciseTemplate
The specific exercise — the atom Hevy, Strong & Jefit all use.
ExerciseTemplate { id: "LEprlgG", // stable, from exercisedb name: "Cable Lat Pulldown", primaryMuscle: "lats", // the TAG secondary: ["biceps"], equipment: "cable", gif, poster, steps }
Why: it's the tested atom — stable id survives renames, muscle/equipment tags power search & swap, and it owns the gif + steps so history is unambiguous.
Block 2 · your addition (the differentiator)
MovementSlot
The layer NO shipping app stores — a real "Vertical pull" slot.
MovementSlot { pattern: "Vertical pull", // WHAT to train targetMuscle: "lats", selectedExerciseId: "LEprlgG", // chosen alternativeIds: ["pullup", "pullover"], scheme: "4×6–10" }
Why: makes "Vertical pull" a first-class thing that owns a chosen exercise + swap options — instead of a loose text label that guesses at a gif.

How swapping works (the payoff)

Before swap
slot.pattern = "Vertical pull" slot.selectedExerciseId = "LEprlgG" → Cable Lat Pulldown
→
Tap "Swap" → pick Pull-up
slot.pattern = "Vertical pull" (unchanged) slot.selectedExerciseId = "pullup" → Pull-up (new gif/steps)
✓ What you gain

The slot stays "Vertical pull" — only the chosen exercise changes. Alternatives are pre-filtered to the same muscle, so swaps always make sense. Logs keep the exercise ID, so history is clean.

↳ What Hevy/Strong do instead

They have no slot — you delete the exercise and add a different one by hand, with no notion that it's "the same movement." Your model makes swapping first-class.

What it takes to build

  1. Restructure the code catalog into exerciseTemplates (fold today's 31 movements + the exercisedb media map into ID-keyed entities with muscle/equipment tags).
  2. Turn each session slot into a MovementSlot — pattern, targetMuscle, selectedExerciseId, alternativeIds[], scheme. All still code-controlled (your no-custom rule).
  3. Add one DB column: workout_slots.exercise_id so logged history references the real exercise, not a text name.
  4. Wire the UI: Train card shows the chosen exercise's gif; a "Swap" action lists the slot's alternatives (filtered by muscle tag). The Add-exercise picker browses by muscle group.
  5. Migrate existing text slots → IDs once (name→id map), keeping the text as a fallback so nothing breaks.
