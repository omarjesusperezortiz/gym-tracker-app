Research — how real apps model it

Ground truth from Hevy's live API spec, Strong's CSV export, Jefit & Fitbod sites.
Gym Tracker · Hevy · Strong · Jefit · Fitbod · verified by curl (no Chrome)
⚡ Headline: None of the four apps use a 3-tier movement-slot layer. All ship 2 tiers — routine → specific exercise directly — with muscle group as a TAG on the exercise. Your 3-tier idea is more structured than any shipping app (a real differentiator), but you should borrow their proven exercise atom and layer your movement slot on top.

What each app actually does

🟣 Hevy 2-tier
live OpenAPI spec · api.hevyapp.com/docs
Routine └─ exercises[].exercise_template_id // direct ref └─ ExerciseTemplate ├─ primary_muscle_group // TAG ├─ secondary_muscle_groups[] └─ equipment
Routine points at a specific exercise by ID. Muscle group is a field on the template, never a slot. Swaps = change the id. superset_id groups exercises.
🔵 Strong 2-tier
real CSV export schema
Workout Name └─ Exercise Name └─ sets (weight, reps…) // NO muscle column at all
Simplest possible model. Flat workout → exercise. Muscle group isn't even stored in the routine/log.
🟢 Jefit 2-tier
jefit.com · 1,294-exercise DB
Plan → Day ("Day 1 – Chest") └─ Exercises // tagged Back / Machine
Middle layer is a training DAY, not a movement slot. Muscle + equipment are tags used only for browsing/filtering.
🟠 Fitbod muscle-aware
fitbod.me · recovery model
Session └─ target muscles // COMPUTED from recovery └─ auto-picked exercises
The only one reasoning at muscle level — but it's a generator algorithm, not a stored schema. The muscle "slot" is transient, not an entity you fill.

The finding, plainly

Industry pattern = (a) routine → specific exercises, muscle group as a tag.

Pattern (b) — persisted, swappable movement slots — is used by nobody. Alternatives/swaps are all faked by editing the routine to point at a different exercise. Your instinct (a real "Vertical pull" slot that owns a chosen exercise + alternatives) is a genuine upgrade over what ships today — the research validates it conceptually (Fitbod's muscle targeting, "alternatives" everywhere) while noting nobody has stored it as an explicit slot.

★ Recommended model — borrow their atom, add your layer

Hevy's exercise foundation + your movement slot on top

Take the battle-tested ExerciseTemplate + muscle-group tag (proven by Hevy), and add the one layer they lack — a real movement slot with a chosen exercise + alternatives.
// LEVEL 3 — the battle-tested atom (adopt Hevy's shape) ExerciseTemplate { id: "LEprlgG", // stable (exercisedb) name: "Cable Lat Pulldown", primary_muscle_group: "lats", // TAG secondary: ["biceps"], equipment: "cable", gif, poster, steps } // LEVEL 2 — YOUR novel layer: the movement slot MovementSlot { pattern: "Vertical pull", // what to train target_muscle_group: "lats", selected_exercise_id: "LEprlgG", // Hevy-style directness alternative_exercise_ids: ["pullup", "pullover"], // first-class swap scheme: "4×6–10" } // LEVEL 1 — Program Program "Pull" { slots: MovementSlot[] }
↳ Borrow from Hevy (proven)
  • • First-class exercise_template with stable id
  • • muscle_group as an enum tag + secondary[]
  • • equipment tag; swaps by exercise id
+ Your addition (the differentiator)
  • ✓ MovementSlot as a real persisted entity
  • ✓ selected + alternatives[] = first-class swapping
  • ✓ filters alternatives by matching muscle/equipment tag
