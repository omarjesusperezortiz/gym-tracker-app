Option B — variations planning

You said B but need to think about which variations. Right. The naive answer — "every movement × every kind gets 3-4 variations" — is ~120 movement/kind pairs × ~3.5 = ~400 exercise entries to curate. That's not shippable in a session and half will never get used. Below is my proposed 3-tier plan so we build the right ~80 first and add on demand.

🎯 The 3-tier strategy

Bucket every movement × kind pair by how much variety actually matters in the real world. Only Tier 1 gets built now.
TIER 1 · BUILD NOW

Movements with real, distinct, popular variations

~10 movements · ~30 entries

Where the variation choice actually changes the training stimulus — different angle, different muscle emphasis, different equipment feel. These are the ones you'd notice in your log.

  • Biceps curl (db) — Hammer / Standing / Incline / Concentration
  • Chest press (db) — Flat / Incline / Decline
  • Vertical pull (cable) — Wide-grip / Close-grip / Underhand / Neutral-grip
  • Horizontal row (db) — 2-arm / Single-arm / Chest-supported
  • Squat (bar) — Back / Front / Goblet
  • Overhead press (db) — Standing / Seated / Arnold
  • Triceps ext (cable) — Rope pushdown / Bar pushdown / Overhead rope
  • Hamstring/RDL (bar) — Conventional / Sumo / Romanian
  • Lunge (db) — Walking / Static / Reverse / Bulgarian split
  • Side lateral raise (cable) — Standing single-arm / Bent / Y-raise
TIER 2 · ADD LATER

Movements with 2 useful variations, low-priority to curate

~10 movements · ~20 entries

Meaningful alternatives exist but the delta is small or you'd rarely rotate. Ship after Tier 1 lands and only if you find yourself wanting them.

  • Incline press · Chest fly · Chest dip
  • Rear delts · Front raise · Shrugs
  • Hammer curl · Overhead triceps · Forearm/wrist
  • Calf raise · Leg raise · Plank
TIER 3 · SKIP

Movements where the current single variation is enough

~11 movements · 0 entries

The exercise is either simple (single canonical form) or the "variations" would be cosmetic — swapping wouldn't change the training in a meaningful way. Leaving these as-is is the right call.

  • Pallof Press, Russian Twist, Side Plank, Reverse Crunch — canonical core work
  • Bicycle Crunch, Air Bike, Butt Lift — canonical core work
  • Upright row, Lat pullover — small, specific movement
  • Bench Dips (bw fallback) — single form
  • Kettlebell Two Arm Military Press — kb has one main form

🏗️ How B actually ships

Once the list above is locked, the code work is predictable.

Implementation plan

  1. Data model: extend variations[movement][kind] from single object to { default: name, options: [{name, mediaId, steps}] }. Backward-compatible: single-variation movements read .default.
  2. Catalog: add the ~30 tier-1 variation entries. Fetch exercisedb demos, upscale to 480px WebP, mirror to public/exercise-media (same pipeline we used for OHP).
  3. Persistence: already covered — exercise_id column already stores the specific variation. No migration needed.
  4. UI — ExerciseCard: when a kind has multiple options, show a small chevron next to the kind tab → tap opens a variation picker sheet. Selected variation drives the demo image, name, steps, and exercise_id on save.
  5. UI — modal: the "Equipment variations" list becomes an "All variations" list (grouped by kind), the active one highlighted.
  6. lastFor: already prefers exact variation match — just works.
  7. Tests: add coverage for multi-variation selection + persistence.

Effort estimate (revised, tier-1 only)

  1. Data model + catalog schema change · ~2 hours
  2. Curate + mirror 30 variation entries · ~½ day (largely automated by exercisedb API + our webp pipeline)
  3. Variation picker sheet on ExerciseCard · ~½ day
  4. Modal update · ~1 hour
  5. Tests + verification · ~2 hours

Total: ~1.5 days shipped. Then tier 2 later, on demand.
